# RAG 缓存失效

## 已实现

- 删除文档：文件删除成功且数据库事务提交后，清除当前用户、当前文档的所有答案缓存。事务回滚不执行清理。
- 重建索引：`POST /api/documents/{id}/rebuild-index`，携带登录 Token，无请求体。校验文档归属后，按 `chunk_index` 顺序读取数据库已有分块，重新生成并覆盖对应向量，不重新切分文件。
- 重建前清缓存，重建成功或异常后再次清缓存。分批向量写入可能部分成功，所以异常后也需要清理。
- 通过 Redis SCAN 分批查找、每批最多删除 200 个键，限定用户和文档，不使用全库清空或 KEYS。

## 故障与边界

- 删除提交后 Redis 清理失败：记录告警，不把已完成的删除报告为回滚；文档权限检查阻止继续访问，残留缓存依靠原有 TTL 过期。
- 重建前 Redis 清理失败：停止重建；重建后清理失败：请求报错，需要恢复 Redis 后重试重建。
- 重建使用已有分块，适用于当前没有文档编辑、重新切分功能的项目；不处理手工修改数据库后留下的多余向量。
- 这是顺序请求下的缓存失效。尚未加入并发版本控制：重建前已开始的问答可能在清理后写回旧答案，重建期间也可能读到部分更新的索引。
- 直接调用 Python `/vectors/upsert` 会绕过 Java 缓存失效；应用重建应通过上述 Java 接口进行。

## 验证

在本地 Redis `localhost:6379` 运行时执行：

```powershell
mvn -f backend/pom.xml '-Djwt.secret=rag-cache-test-only-secret-0123456789abcdef' '-Drag.cache.redis-test=true' test
```

本次 31 项测试通过：

- 模拟提交和回滚回调，验证清理时机、权限拒绝及删除失败。
- 模拟 AI 服务，验证重建前后清理、部分写入失败后的清理、Redis 故障时停止重建。
- 真实 Redis 验证 205 个问题缓存批量清除，其他用户与文档缓存保留，清理后可重新写入。
- 原有重复问答命中和 TTL 过期测试通过。

测试未调用真实 Embedding / LLM API，也未执行真实业务文档删除。
