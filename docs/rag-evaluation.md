# RAG 评测 v0

状态：已完成两组共40次真实服务问答和Codex评分，独立人工复核待完成。

## 数据与参数

- 使用 [虚构试运行手册](evaluation/handbook.txt)，其参数用于测试，不代表当前项目功能承诺。
- [20 道固定问题和期望答案](evaluation/questions.json)：事实、改写、推算、综合和文档外问题。期望答案在调用模型前固定。
- 每块500字符，重叠50字符，生成5块；比较 TopK=3 与 TopK=5，每组20次问答。TopK=5覆盖全文，本轮不改变分块参数。
- 通过 FastAPI 检索和生成接口评测，使用专用负数文档编号，跳过 Java 与 Redis 缓存。不会验证鉴权、历史、Java 超时或上传全链路。
- 专用文档会保留在本地 Chroma 中；正常业务正数文档编号不会匹配该文档。

## 复现

先在启动 FastAPI 的终端配置真实 LLM 和 Embedding 密钥。不要把密钥提交到仓库。

```powershell
python docs/evaluation/run_evaluation.py
```

脚本分批写入索引并逐条保存 results-*.json，保留问题、期望答案、原始答案、来源和耗时。Mock 答案不能算正式评测。模型型号由服务启动配置决定，报告应另行记录；当前接口不提供型号查询。

## 评分规则

人工逐题检查并填写原始结果中的 review：

- answer_correct：包含期望要点且无矛盾。文档外题必须明确拒答，不补充无依据的具体参数。
- source_sufficient：来源包含回答所需证据；综合题必须覆盖全部要点。文档外题该项记为不适用。
- unsupported_claims：回答是否包含文档无法支持的事实。
- notes：引用原始结果中的 chunk_index，说明失败来自检索遗漏、生成错误或无依据补全。

两组分别统计：正确答案数/20、来源充分数/16、文档外正确拒答数/4、请求错误数；错误请求计入20题分母。耗时包含检索与生成，不与 Redis 命中耗时比较。本轮每题只运行一次，不能把小样本差异视为稳定优势。

### 差异与失败分析

第7题两组均返回正确存储路径与随机文件名，但对同一用户同名上传是否覆盖表示文档未明确说明。依据预先固定的期望，严格判为部分回答。来源chunk 1已经命中，因此不是检索遗漏；原因涉及题目范围含糊与模型保守推断。后续可明确区分“不同用户同名文件”与“随机命名的作用”，不能改写本轮题目后追认通过。

其余19题两组均通过，没有为了凑数量制造失败案例。本轮文档外题含明确的“未规定”表述，拒答难度较低；文档只有5块，TopK=5相当于全文输入。当前样本不足以证明真实长文档、跨块复杂问题的效果。

本轮TopK=5未提高正确率，保留TopK=3作为当前基准；不据单次顺序运行的耗时推断稳定性能优势。后续需要更长文档、没有显式否定提示的文档外题和重复运行。
